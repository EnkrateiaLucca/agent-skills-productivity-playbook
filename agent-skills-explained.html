Agent Skills

A folder that teaches Claude how you work. Write it once, and it loads itself whenever a request matches — costing almost nothing until it does.

What a Skill is

A Skill is a directory containing instructions in Markdown, plus optional scripts and reference files. Claude reads it from the filesystem with bash when your request matches its description.

Think onboarding guide for a new hire, not plugin. It carries procedural knowledge: workflows, house style, domain rules.

ThingWhat it gives Claude
PromptOne-off instructions, this conversation only
MCP serverAccess to tools and live data — what Claude can do
SkillWorkflow knowledge — how Claude should do it
MCP is the professional kitchen. A Skill is the recipe. Users with both accomplish complex tasks without figuring out every step themselves.

Progressive disclosure

Content loads in levels. Click a level to see what enters the context window.

Two consequences matter. Installing many Skills costs almost nothing until one fires. And bundled content is effectively unbounded — a Skill can ship a 200-page API reference that costs zero tokens on every request that doesn't need it.

Scripts are the sharpest tool here. The code never enters context, only its output, and execution is deterministic where language interpretation is not.

File structure

your-skill-name/
├── SKILL.md          # required — instructions + YAML frontmatter
├── scripts/          # optional — executable code
│   └── validate.py
├── references/       # optional — docs Claude reads as needed
│   └── api-guide.md
└── assets/           # optional — templates, fonts, icons used in output
    └── report-template.md

Hard rules

  • The file is named exactly SKILL.md. Case-sensitive, no variations.
  • Folder name in kebab-case: notion-project-setup. No spaces, underscores, or capitals.
  • No README.md inside the Skill folder. Docs go in SKILL.md or references/. A repo-level README for human visitors is separate and fine.
  • name: max 64 chars, lowercase letters, numbers, hyphens. Cannot contain "claude" or "anthropic" — reserved.
  • description: non-empty, max 1024 chars.
  • No XML angle brackets anywhere in the frontmatter. It lands in the system prompt, so this is an injection guard.

Frontmatter

Minimum viable:

---
name: your-skill-name
description: What it does. Use when the user asks to [specific phrases].
---

Optional fields:

license: MIT
compatibility: Requires Python 3.11 and network access   # 1–500 chars
allowed-tools: "Bash(python:*) Bash(npm:*) WebFetch"
metadata:
  author: Company Name
  version: 1.0.0
  mcp-server: server-name

The description does all the routing work

It is the only thing Claude sees before deciding to load the Skill. Structure it as what it does + when to use it + trigger phrases.

Good

description: Analyzes Figma design files and generates developer handoff
  documentation. Use when the user uploads .fig files, asks for "design specs",
  "component documentation", or "design-to-code handoff".

Bad

description: Helps with projects.                          # too vague
description: Creates multi-page documentation systems.     # no triggers
description: Implements the Project entity model.          # no user language

Check yours

Heuristics only — they catch the mechanical failures, not whether the description reads well.

Writing the body

# Skill Name

## Instructions
### Step 1: [First major step]
What happens, and the exact command:
`python scripts/fetch_data.py --project-id PROJECT_ID`
Expected output: [what success looks like]

## Examples
User says: "Set up a new marketing campaign"
Actions: 1. Fetch existing campaigns  2. Create with parameters
Result: Campaign created with confirmation link

## Troubleshooting
Error: [message] → Cause: [why] → Solution: [fix]

Rules that hold up in practice:

  • Be specific and runnable. "Run python scripts/validate.py --input {file}" beats "validate the data before proceeding."
  • Put critical instructions at the top. Buried rules get skipped.
  • Replace ambiguous language with explicit checks: "CRITICAL: before calling create_project, verify name is non-empty, one team member assigned, start date not in the past."
  • For validations that must not fail, bundle a script instead of trusting prose.
  • Keep SKILL.md under ~5,000 words. Push the rest into references/ and link it.
  • Skills compose. Assume others are loaded alongside yours.

Where Skills live

SurfaceHow to installSharing scope
Claude Code~/.claude/skills/ (personal) or .claude/skills/ (project)Personal, project, or via plugins
claude.aiSettings → Capabilities → Skills, upload a zipPer user; admins can deploy org-wide
Claude API/v1/skills, referenced in container.skillsWorkspace-wide
Skills do not sync across surfaces. Upload separately to each one you want them on.

Runtime differs too. Claude Code gives full network access and normal filesystem reach. The API sandbox has no network access and no runtime package installation — preinstalled packages only — and requires the code execution tool.

Testing

  1. Triggering. Run 10–20 queries. Fires on obvious asks and paraphrases, stays quiet on unrelated ones. Aim for ~90% on relevant queries.
  2. Function. Correct outputs, successful tool calls, error paths, edge cases.
  3. Baseline comparison. Same task with and without the Skill. Count messages, tool calls, failures, tokens.
Debugging trick. Ask Claude: "when would you use the [skill-name] skill?" It quotes the description back, which shows you exactly what's missing.

Fastest path to a good Skill: iterate on one hard task in a normal conversation until Claude gets it right, then extract that winning approach into a Skill. Expand to more cases afterward.

Failure modes

SymptomFix
Never triggersDescription too generic. Add trigger phrases, technical keywords, file types.
Triggers on everythingNarrow the scope; add negative triggers — "Do NOT use for X, use the Y skill instead."
Loads but instructions ignoredToo verbose, buried, or ambiguous. Trim, move critical rules to the top, replace prose checks with scripts.
Slow or degraded responsesSKILL.md too large, or too many Skills enabled. Move detail to references/; audit if you have 20–50+ enabled.
Won't uploadSKILL.md misspelled, missing --- delimiters, unclosed quotes, or a name with spaces/capitals.

Patterns

Three common Skill shapes:

  • Document and asset creation — embedded style guides, templates, quality checklists. No external tools needed.
  • Workflow automation — step-by-step processes with validation gates and refinement loops.
  • MCP enhancement — sequences multiple MCP calls, embeds domain expertise, handles common API errors.

Useful patterns within those: sequential orchestration with explicit dependencies and rollback; multi-MCP coordination in phases; iterative refinement against a quality script; context-aware tool selection via a decision tree; domain rules applied before action, with an audit trail.

Security

Install Skills only from sources you trust. A Skill directs Claude to run code and invoke tools, so a malicious one can exfiltrate data or misuse system access.

Audit every bundled file — SKILL.md, scripts, assets — for network calls or file access that doesn't match the stated purpose. Skills that fetch external URLs carry extra risk: fetched content can carry instructions, and remote dependencies can change after you vetted them. Treat installing a Skill like installing software.
